Quick Reference Sheet

AI System Design: 4-Phase Interview Framework

A battle-tested blueprint for Senior and Staff AI & ML System Design interviews (45–60 min loops).

⏱ Allocation: 45 min total 🎯 Target: Senior / Staff Level 🔗 Go to Lesson 0001

The 45-Minute Interview Blueprint

00–08m
Phase 1
Clarification, Scope & Non-Functional SLAs

Define functional user story. Nail down QPS, peak RPS, latency budgets (TTFT & TPOT), context window limits, freshness, availability, and hardware budget.

08–22m
Phase 2
End-to-End High-Level Architecture

Draw the complete block diagram: ingestion pipeline (offline) vs. inference & serving pipeline (online). Establish clean component seams, data contracts, and storage choices.

22–37m
Phase 3
Deep Dive: AI Bottlenecks & Distributed Scale

Analyze memory bandwidth vs. compute bottlenecks. Detail serving infra (vLLM, continuous batching, PagedAttention, KV cache sizing, model parallelism, vector indexing).

37–45m
Phase 4
Operational Resilience, Evals & Guardrails

Define the offline/online evaluation flywheel (RAG triad, LLM-as-judge). Detail guardrails, fallback paths, graceful degradation, and system telemetry.

Phase 1: Essential Scoping Checklist & Metrics

1. Functional Requirements

  • What is the core user experience? (Chat, autocomplete, agent task, batch report)
  • Input modality & typical length (e.g., 2k tokens text, PDF, audio).
  • Output modality & expectation (Streaming tokens vs atomic JSON response).

2. Non-Functional SLAs

  • Throughput: Average QPS and peak burst factor (e.g., 50 QPS avg, 200 peak).
  • TTFT (Time to First Token): < 300–500ms for conversational UI.
  • TPOT (Time Per Output Token): < 30–40ms (~25–33 tokens/sec).
  • Freshness: Static weights, daily updates, or real-time streaming data?

Critical Back-of-the-Envelope Formulas

Demonstrating rapid, accurate memory and throughput sizing separates Staff candidates from junior applicants.

1. Model Weights Memory Footprint:
Memory (Bytes) ≈ Parameters × Bytes Per Parameter
• FP16 / BF16 = 2 bytes/param  →  70B model = 140 GB VRAM (bare minimum weights only)
• INT8 = 1 byte/param  →  70B model = 70 GB VRAM
• INT4 / AWQ = 0.5 bytes/param  →  70B model = 35 GB VRAM
2. KV Cache Memory per Active Request:
KV Memory (Bytes) = 2 × n_layers × n_heads_kv × d_head × seq_len × bytes_per_elem
Note: For GQA (Grouped Query Attention), n_heads_kv is significantly smaller than query heads (e.g., 8 KV heads vs 64 query heads in Llama 3 70B), slashing KV cache overhead by 8x.
3. Cluster Sizing for Peak Load:
Total Peak Output Tokens/sec = Peak QPS × Avg Output Tokens Per Query
GPUs Needed = Total Peak Output Tokens/sec ÷ Max Sustainable Output Tokens/sec per GPU

Phase 2 & 3: Core Architecture Seams

Subsystem Standard Production Choice Staff Architectural Justification
Serving Engine vLLM / TensorRT-LLM / TGI PagedAttention eliminates 60–80% internal memory fragmentation; continuous (iteration-level) batching keeps GPU SM utilization high during mixed prefill/decode phases.
Retrieval Index HNSW (Hierarchical Navigable Small World) Offers superior recall vs. latency trade-off compared to IVF; can be paired with scalar quantization (SQ8) to cut memory overhead in half.
Hybrid Search BM25 + Dense Embeddings + RRF Dense retrieval fails on exact entity codes, serial numbers, and acronyms; BM25 catches keywords; Reciprocal Rank Fusion normalizes disparate scoring scales cleanly.
Semantic Cache Redis Vector Search / GPTCache Saves costly generation for high-repetition prompts, but requires a strict cosine distance threshold (> 0.95) and strict cache invalidation on underlying context change.
Inference Parallelism Tensor Parallelism (TP) across NVLink 70B FP16 requires 140GB+; splitting across 2x or 4x A100/H100 with TP is optimal due to 900 GB/s NVLink interconnects. Do not split TP over standard PCIe or Ethernet.

Phase 4: Evaluation & Observability Matrix

Offline Evaluation Flywheel

  • Context Relevance: Is the retrieved text relevant to the prompt? (RAG Triad 1)
  • Groundedness / Faithfulness: Is the answer derived strictly from context? (RAG Triad 2)
  • Answer Relevance: Does the output directly satisfy the user query? (RAG Triad 3)
  • Curated Golden Eval Benchmark (200–500 hand-verified queries run on every prompt/code commit).

Online Monitoring & Guardrails

  • Telemetry: Track p50, p95, p99 TTFT and TPOT; token count distributions; cache hit rates.
  • Guardrails: Input sanitization (prompt injection classifier) and output validation (PII scrubbing, format schemas via outlines/json-mode).
  • Fallback Circuits: Degradation to smaller cached models or degraded retrieval mode if primary model servers breach timeout.

Senior vs. Staff Interview Trap Matrix

Scenario The Junior / Pure ML Trap The Staff AI Systems Approach
"Design a real-time AI code completion tool" Spends 20 minutes discussing which transformer model or loss function to train. Anchors latency constraint first: TTFT must be < 50ms. Concludes that local edge model or speculative decoding with a small draft model is strictly required.
"Design an enterprise documentation RAG system" Says: "We chunk docs into 500 tokens, embed with OpenAI, put in Pinecone, and send top-5 to Claude." Analyzes chunk overlap, metadata filtering by tenant, hybrid BM25 + dense search with reranker, prefix-prompt caching, and an automated eval harness.
"How do you handle sudden 10x traffic spikes?" "Just auto-scale the GPU instances in Kubernetes." Notes GPU cold-start times (5–10 mins to pull 40GB weights); introduces queue-based rate limiting, prefix caching, model quantization fallbacks, and pre-warmed replica pools.
